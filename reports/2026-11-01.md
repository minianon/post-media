[160 chars] 1/4 Your API is public. One client sends 10,000 requests a minute, and now everyone else is slow.

Rate limiting is the fix. Here's where it sits, in 4 tweets 🧵

[198 chars] 2/4 The limiter sits in front of your API servers.

Each request is checked against a limit for that client (API key, user or IP). Under the limit: it passes through. Over it: 429 Too Many Requests.

[225 chars] 3/4 Two common algorithms:

- Token bucket: tokens refill at a steady rate, each request spends one. Allows short bursts.
- Window counter: count requests per time window. Simpler, but fixed windows can spike at the boundary.

[233 chars] 4/4 With many API nodes, the counters must live in a shared store, not in each server's memory. Otherwise every node enforces its own limit.

More: https://github.com/minianon/System-Design

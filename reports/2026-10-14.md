The PIN on my own app is not security. I wrote that in the README on purpose.

AnonVault is my private workspace: checklists, hackathon deadlines, ideas, a review of my streaks. It opens behind a 4-digit PIN.

Here is what that PIN really does:
- The Vite env variables are inlined into the JavaScript bundle, so the PIN and the Supabase anon key are readable in the browser
- The "authorized" flag lives in sessionStorage, so anyone can set it from devtools
- The schema in the repo ships with Row Level Security off, and in that setup anyone with the URL and key can call the database API without opening the UI

So it is a privacy screen against someone glancing at my laptop. Nothing more.

The lesson: a check that runs only in the client is a suggestion, not a rule. Real access control belongs on the server, in the database policies: RLS plus an authenticated user, scoped to that user's rows.

I would rather document the limit than let a lock icon imply protection it does not give.

Try it: https://vault.minianon.in
Code: https://github.com/minianon/AnonVault

Have you ever shipped a client-side check and later realised the server never enforced it?

My debugging order when something breaks:

1. Read the actual error message, fully
2. Reproduce it reliably
3. Ask "what changed since it last worked?"
4. Bisect: cut the problem space in half
5. Only then ask for help, with steps

Most bugs die by step 3.

1/5 Long polling vs WebSockets vs SSE: how does a server push data to a browser? Explained in 5 tweets 🧵

2/5 The problem: HTTP is client-initiated. The server can't just send something on its own.

These three are the common ways around that.

3/5 Long polling: the client asks, the server holds the request open until there's an update (or a timeout), then the client asks again.

Easy and widely supported, but a new connection every time, so it doesn't scale well.

4/5 WebSockets: one persistent connection, both sides can send any time (full-duplex). Lightweight, great for chat.

SSE: the server streams events one way, client to server needs a normal request. Simple, but no binary data.

5/5 My notes on all three: https://github.com/minianon/System-Design

Chat app or live score ticker: which would you build with SSE, and which with WebSockets?

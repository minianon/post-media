Nobody tells freshers this about off-campus hiring:

Recruiters don't reject you for a missing skill. They reject you because they can't verify one.

What I'd do again, in this order:

1. Build one project that does one thing well
2. Put it on a live link, not just a repo
3. Write a short, specific message (what you built, why this team)
4. Practise explaining your decisions out loud
5. After every round, write down what you fumbled. Then repeat.

A live link answers "can this person ship?" before the first call.

A specific message beats a polished generic one every time.

And out-loud practice matters more than your 500th solved problem.

Small steps, every day.

1/4 Your LLM call will fail in production. Not might. Will.

Timeouts, rate limits, malformed output.

Here's the pattern I use so users never see it 🧵

2/4 Try the strong model first (in ShortlistMe: Llama 3.3 70B on Groq).

Ask for strict JSON so the output is parseable, not prose.

3/4 On timeout or API error, don't crash. Fall back to a smaller, faster model (Llama 3.1 8B).

A slightly weaker answer beats an error page.

4/4 Only after every model fails, raise a clear error and let the user retry.

See it in action: https://shortlistme.site

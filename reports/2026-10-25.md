1/5 You type example.com and a page loads. But your browser needs an IP address first. Here's how a DNS lookup finds it, in 5 tweets 🧵 (134 chars)

2/5 Step 1: your browser asks a DNS resolver. The resolver checks its cache first. If it already knows the answer, it replies instantly and the lookup ends here. (161 chars)

3/5 Cache miss? The resolver asks a root server. The root doesn't know the IP, but it points to the right TLD server for the extension, like .com or .org. (154 chars)

4/5 The resolver then asks the TLD server, which points to the domain's authoritative nameserver. That server holds the real record (an A record maps the name to an IP) and returns it. (184 chars)

5/5 The resolver sends the IP back to your browser and caches it for the record's TTL. My notes on DNS and more: https://github.com/minianon/System-Design

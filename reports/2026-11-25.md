A canvas editor with no backend and no login. Here is how Canvas Editor works.

Canvas Editor is a small 2D editor I built: shapes, text, a pen tool and a colour picker. You create a canvas and get a link you can share.

The whole design fits in three steps:
- The home page adds one Firestore document with an empty canvasJSON, then redirects to /canvas/:id
- The editor loads that document and restores the objects with Fabric.js loadFromJSON
- Save writes canvas.toJSON(), stringified, back to the same document with a merge

So the URL is the document ID, and the whole canvas is a single JSON string. That is why there are no accounts and no server code.

The trade-offs are written in the design docs too: anyone with the link can edit, saving is manual, and there is no realtime collaboration. I would rather document the limits than hide them.

Lesson: a boring data model (one document, one string) can carry a surprising amount of product.

1/4 You type a URL and press enter. Before any HTTP request goes out, your browser and the server do a quick three-step greeting first.

It's called the TCP three-way handshake.

[193 chars]
2/4 Step 1, SYN: the client says "I want to connect" and shares the sequence number it will start from.

Step 2, SYN + ACK: the server says "got it" and shares its own starting sequence number.

[218 chars]
3/4 Step 3, ACK: the client confirms.

Now both sides agree the connection is open and reliable, and real data can flow. In "what happens when you hit a URL", this sits after the DNS lookup and before the HTTP request.

[210 chars]
4/4 Why three steps and not two? Each side has to prove it can both send and receive.

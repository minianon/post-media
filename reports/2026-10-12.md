Your query is slow. Before you add more servers, ask: is there an index?

A database index is a data structure that gives a quick lookup on one or more columns.

Without it, "WHERE email = ?" checks every row in the table.
With it, the database searches the index and jumps straight to the row.

The trade-off nobody mentions in the first lecture:
- Indexes take extra memory
- Every insert and update has to maintain them
- So index the columns you actually search on, not everything

Clustered vs non-clustered, the interview favourite:
- A clustered index changes how the rows are physically stored, based on the indexed column
- A non-clustered index is a separate structure that points back to the table
- A table can have only one clustered index, but many non-clustered ones

Easy way to remember it: clustered is the order of the book's pages, non-clustered is the index at the back.

1/5 Layer 4 vs Layer 7 load balancing, explained in 5 tweets. Interviewers love this one 🧵

2/5 A load balancer spreads traffic across servers and only sends requests to ones that are online. That's how you add or remove servers without downtime.

3/5 Layer 4 works at the network/transport level. It sees IP addresses and ports, nothing else. Very fast, but it can't route by what's inside the request.

4/5 Layer 7 works at the application level. It reads the whole request, so it can send /api to one group of servers and /static to another. Smarter, a bit more work per request.

5/5 My notes on this, plus DNS, TCP vs UDP and more: https://github.com/minianon/System-Design

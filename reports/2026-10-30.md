1/4 Your database is slow under read load. The usual first fix: put a cache in front of it.

The most common pattern is cache-aside. Here's how it works.

2/4 The app owns the logic:

1. Check the cache for the key
2. Hit? Return it
3. Miss? Query the database
4. Write the result to the cache with a TTL

The cache never talks to the database itself.

3/4 Watch out for:

- Stale data: the DB changes, the cache doesn't until the TTL ends
- Cold start: every key misses at first
- Stampede: a hot key expires and many requests hit the DB at once

4/4 Rule of thumb: cache-aside suits read-heavy data that can be a little stale. Pick TTLs on purpose, and delete the key on writes.

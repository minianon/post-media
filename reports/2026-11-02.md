#2 · 6:00 PM · Thread (4 tweets) · System Design · consistent hashing with virtual nodes
🖼 https://raw.githubusercontent.com/minianon/post-media/main/2026/11-02/x-1800-1.png (on tweet 1)
1/4 You have 4 cache servers and route keys with hash(key) % 4. Add a fifth, and almost every key lands on a different server.

Consistent hashing fixes that. Here's the idea in 4 tweets 🧵

2/4 Put servers and keys on the same hash ring.

A key is served by the first server found going clockwise from its position. Add or remove a server and only the keys on its arc move, roughly K/N of them.

3/4 Problem: with few servers, arcs come out uneven and one server gets more load.

Fix: virtual nodes. Each physical server is hashed onto the ring many times, so it owns many small arcs and the load evens out.

4/4 Bonus: when a server dies, its arcs are spread across the others instead of dumping everything on one neighbour.

More: https://github.com/minianon/System-Design
